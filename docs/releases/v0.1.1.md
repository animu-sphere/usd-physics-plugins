# v0.1.1 — a six-DOF package beside physicsJolt

**Release status:** the tag `v0.1.1` is cut from the commit that adds this record,
after a green dry run of the [release workflow](../../.github/workflows/release.yml)
on `main`. The draft is published once `usd-avatar-runtime`'s MMD session lanes pass
on the pushed digests, the downstream check the
[release schema](../architecture/RELEASE_SCHEMA.md#3-promotion-gates) requires for a
new library.

## What ships

`physicsCore`, `physicsJolt` and `physicsUsd` as in v0.1.0, and the new
`physicsJoltSixDof`, each as its own digest-pinned artifact. The
[changelog](../../CHANGELOG.md) lists the changes.

## Compatibility

- **Targets:** `cy2026` / `usd` on Windows x86_64 and Linux x86_64, with OpenUSD
  26.08 and Python 3.13.
- **`physicsJolt`:** its Jolt options and its six-DOF capability, which is off, are
  unchanged. Existing consumers need no change beyond the new digests.
- **`physicsJoltSixDof`:** the same sources with six-DOF on, built on the
  [deterministic Jolt SDK](../architecture/DEPENDENCIES.md#3-jolt-physics). It installs
  the same `physicsJolt` CMake package and target, so a consumer pins one of the two
  and builds Jolt with the matching options. Each refuses the other's SDK when a
  consumer configures.

## Known limitations

- Six-DOF constraints and neutral springs stay experimental: this adds a package to
  pin, not a stability promise.
- The two backends cannot share a process, because their Jolt SDKs are different ABI
  sets.
